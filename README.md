# پروژه‌ی بات WoW - خلاصه‌ی کامل

## هدف پروژه
ساخت یه بات ماژولار مبتنی بر بینایی ماشین (Computer Vision) + یه ادان کمکی، برای اجرا
روی یه **سرور شخصی** World of Warcraft (نه سرور رسمی بلیزارد)، جهت فارم/گرایند خودکار:
پیدا کردن دشمن، نزدیک شدن، مبارزه، لوت کردن، و تکرار - همراه با لایه‌های ایمنی و
رفتار طبیعی‌تر (کمتر ماشینی).

## معماری کلی

```
┌─────────────────────────────────────────┐
│  WoWBotBridge (ادان داخل بازی)            │
│  هر 0.2 ثانیه: HP/Focus/موقعیت/هدف رو     │
│  می‌نویسه (فایل مستقیم یا چت‌فریم مخفی)     │
└───────────────────┬───────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  bridge_reader.py (AutoBridge)            │
│  می‌خونه، پارس می‌کنه، خودش تشخیص می‌ده      │
│  کدوم روش انتقال فعاله                    │
└───────────────────┬───────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────┐
│  fsm.py (مغز اصلی)                        │
│  SCAN → MOVE_TO → COMBAT → LOOT → ...     │
│  + FLEEING در HP بحرانی                   │
└──────┬──────────────────┬─────────────────┘
       │                  │
       ▼                  ▼
┌─────────────┐   ┌──────────────────┐
│controller.py│   │ enemy_vision.py   │
│(کلید/موس)   │   │ (تشخیص دشمن از    │
└─────────────┘   │  تصویر ویوپورت)   │
                   └──────────────────┘

لایه‌های مکمل که همه‌جا استفاده می‌شن:
- humanize.py   -> تایمینگ/رفتار نامنظم و طبیعی‌تر
- watchdog.py   -> تشخیص گیر کردن/مرگ/قطعی و توقف اضطراری (Kill Switch: F10)
- screen_capture.py -> گرفتن فریم مشترک برای ماژول‌های بینایی (بهینه‌سازی)
```

## فایل‌های پروژه

### ادان (نصب در بازی)
- `addon/WoWBotBridge/WoWBotBridge.toc` - فایل معرفی ادان
- `addon/WoWBotBridge/WoWBotBridge.lua` - منطق اصلی export وضعیت بازیکن

### پایتون
- `python/bridge_reader.py` - خوندن و پارس کردن دیتای ادان (کلاس اصلی: `AutoBridge`)
- `python/controller.py` - اجرای اکشن‌های کیبورد/موس
- `python/enemy_vision.py` - تشخیص دشمن از تصویر (جهت + لیست کامل + انتخاب هدف)
- `python/screen_capture.py` - گرفتن فریم مشترک برای همه‌ی ماژول‌های CV
- `python/humanize.py` - تصادفی‌سازی تایمینگ و رفتار برای طبیعی‌تر شدن
- `python/watchdog.py` - سیستم ایمنی مستقل (گیر کردن، مرگ، قطعی، Kill Switch)
- `python/fsm.py` - ماشین حالت اصلی که همه‌چیز رو به هم وصل می‌کنه (نقطه‌ی ورود اجرا)

## چی کار کردیم (خلاصه)

| بخش | وضعیت |
|---|---|
| ارتباط بازی ↔ پایتون (ادان + بریج) | ✅ ساخته و تست‌شده (با داده‌ی شبیه‌سازی‌شده) |
| تشخیص دشمن از تصویر (جهت + لیست) | ✅ ساخته و تست‌شده |
| کنترلر کیبورد/موس | ✅ ساخته |
| FSM اصلی (چرخه‌ی گرایند کامل) | ✅ ساخته و تست‌شده |
| تشخیص "هدف مرده" vs "هدف گم‌شده/فرار کرده" | ✅ ساخته و تست‌شده |
| رفتار شبیه‌انسان (تایمینگ متغیر، مکث‌های تصادفی) | ✅ ساخته و تست‌شده |
| Safety/Watchdog (گیر کردن، مرگ، Kill Switch) | ✅ ساخته و تست‌شده |
| فریم‌گیری مشترک برای بهینه‌سازی CV | ✅ ساخته و تست‌شده |
| **تست روی بازی واقعی** | ❌ هنوز انجام نشده |

**نکته‌ی مهم:** همه‌ی تست‌ها تا این لحظه با داده‌ی شبیه‌سازی‌شده (mock) بودن، نه بازی
واقعی. کالیبراسیون‌های رنگ/ابعاد (HSV و غیره) از قبل از این پروژه به ارث رسیدن و
حداقل یکی‌شون (مینی‌مپ) طبق گفته‌ی کاربر درست کار نمی‌کرد؛ به همین خاطر مسیر
جهت‌یابی رو از مینی‌مپ به enemy_vision.py (نیم‌پلیت دشمن در تصویر جلوی کاراکتر)
تغییر دادیم.

## چی مونده

1. **تست واقعی روی بازی** - مهم‌ترین قدم بعدی
2. **Rotation واقعی** - الان فقط چرخه‌ی ثابت (1,2,3) هست
3. **Corpse Run خودکار** - عمداً ساخته نشد (بدون مختصات دقیق دنیا، ریسک بالایی داره)
4. **Gathering (Herb/Ore)** - شروع نشده
5. **تنظیم دقیق HSV/ابعاد enemy_vision** پس از دیدن رفتار واقعی

## نحوه‌ی تست (خلاصه)

1. ادان رو کپی کن به `Interface/AddOns/WoWBotBridge/`
2. `pip install pydirectinput mss opencv-python numpy keyboard`
3. تست تک‌تک: `bridge_reader.py` تنها -> `enemy_vision` تنها -> `controller` تنها
4. اگه همه جواب داد: `python fsm.py "C:\Path\To\WoW"`
5. حین اجرا: دست روی Kill Switch (F10)، اول فقط نگاه کن دخالت نکن

## یادآوری مهم
این پروژه با فرض صریح **سرور شخصی خود کاربر** ساخته شده، نه سرور رسمی بلیزارد.
هرگونه استفاده روی سرور رسمی نقض ToS بلیزارده و ریسک بن دائم اکانت داره.
