# Phase 12 Results — Laboratory Control Stack Stability

Perception mode: MOCK (real perception not yet enabled).
Phase 13 is where functional/outcome evaluation begins.

---

## 1. Title and Phase Identifier

This document presents the stability analysis and execution findings for Phase 12 of the WoW-bot research prototype. Phase 12 serves as the final stability checkpoint prior to integrating real perception in Phase 13.

- **Phase Identifier:** Phase 12 (Soak & Final Analysis)
- **Perception Mode:** MOCK (synthetic perception provided via `MockPerception`; real screen/memory perception is not active).
- **Execution Scope:** Software control stack stability, resource bounding, and aggregate report verification under MOCK execution.
- **Phase Boundary:** Phase 13 is where functional/outcome evaluation begins.

---

## 2. Scope and Non-Claims

Phase 12 is strictly a stability phase, not a performance or functional evaluation phase. Its primary objective is to demonstrate that the asynchronous control loop, FSM, navigation, combat, watchdog, and humanization infrastructure can run continuously for a 1-hour soak under synthetic input without crashing, leaking memory, or experiencing unhandled internal failures.

Per `docs/SOAK_PROTOCOL.md`, all results in this report are published alongside the following explicit non-claims:

- We do NOT claim the agent farmed successfully in a real game. Perception was mocked; outcomes were not observed.
- We do NOT claim anti-cheat evasion.
- We do NOT claim humanizer timing would evade detection.
- We do NOT claim 24-hour stability. Only 1 hour was measured in Phase 12.

## 5. Resource Behavior Discussion

### CPU Usage
CPU utilization remained stable throughout the 1-hour run, exhibiting a mean process CPU usage of approximately 12.50% and a peak burst of 30.76%. There was no indication of runaway event loops, unbounded async task accumulation, or thread starvation.

### RSS Memory Trend
Process resident set size (RSS) remained strictly bounded throughout the execution. No unbounded memory growth or object accumulation was detected.

*Note on Metric Behavior:* In `soak_report.json`, `rss_slope_bytes_per_hour` is reported as a slight positive value even when `rss_end_bytes` is lower than `rss_start_bytes`. This occurs because the slope is computed using linear regression over a trailing sliding window (`memory_slope_window = 300` samples) rather than across the entire 1-hour duration. This discrepancy is recorded as a metric-definition review item for future analytical refinements and does not indicate a true memory leak.

### Log Growth
The `log_size_bytes` metric was recorded as 0 bytes for the application log file sampler, while structured JSON Lines events were written incrementally to `events.jsonl` without buffer clogging or stream truncation.

## 6. Cross-Session Aggregate Findings

The cross-session aggregate report `runs/lab/aggregate-1h/aggregate_v1.json` was generated by `src/wow_bot/analysis/aggregate.py` (schema version 1) over the soak session directory `runs/lab/soak-1h/`.

Key aggregate properties:
- **`session_count`:** 1
- **`session_ids`:** `["soak-1h-20260922"]`
- **`report_count`:** 0
- **`soak_report_count`:** 1
- **`internal_counters_not_research_findings`:** All fields (`cycle_success_rate`, `cycle_failure_rate`, `mean_distance_to_target`, `farm_outcome_count`) are `null`.

### Scope Split Explanations:
1. **`internal_counters_not_research_findings` is all `null`:** By design, Phase 12 uses MOCK perception, where outcome-dependent metrics (distance to target, farm success, item counts) cannot be observed. Setting these fields to `null` prevents synthetic mock artifacts from being reported as research findings.
2. **`report_count = 0` and `soak_report_count = 1`:** The post-processing pipeline (`lab_pipeline_v2.py`) produces `report_v2.json` for standard execution sessions, whereas long-running soak sessions produce `soak_report.json` via `lab_soak_v2.py`. This structure is consistent with the T10/T12 architecture separation.

## 7. Observations Deferred to Phase 13

During analysis of `events.jsonl` from the Phase 12 soak run, several operational behaviors were observed. None of these constitute Phase 12 stability failures; they are formally recorded as items to be evaluated when real perception is enabled in Phase 13:

1. **Strategist Goal Rejection Pattern:** The event log contains a repeating sequence where `cooldown_allowed` is followed by `vocab_rejected` with goal `"farm"` and rejection reason `"unknown_goal"`. In Phase 13, either the allowed vocabulary (`ALLOWED_GOALS` in `vocab_v2.py`) must be expanded to include a farm goal or the strategist prompt must strictly constrain goal generation to valid vocabulary entries.
2. **Target Visibility in World Sync:** The `target_seen` boolean was consistently `false` in `world_sync` session events. This is expected under synthetic mock perception and will be evaluated with real perception.
3. **Reflex Tick Rate Zero:** `reflex_ticks_total` was 0 because the reflex loop was excluded from the MOCK soak configuration per `SOAK_PROTOCOL.md`.
4. **Zero Outcome Totals:** `successful_actions_total`, `position_delta_total`, and `inventory_delta_total` were all 0. This is expected behavior for MOCK perception with synthetic inputs and is not a failure.
5. **Node Creation Fluctuation:** `player_node_created` alternated between `true` and `false` in `world_sync` events, representing proximity node evaluation in synthetic spatial sync.

## 8. Determinism and Reproducibility

Cross-session aggregate generation is strictly deterministic. Given identical input report files and a fixed `now` timestamp string, `aggregate_sessions()` produces byte-for-byte identical output.

- **Canonical Artifacts:** The soak session directory `runs/lab/soak-1h/` is the canonical source artifact.
- **Aggregation Invocation Reference:**
  ```python
  run_aggregate(
      [Path("runs/lab/soak-1h")],
      output_dir=Path("runs/lab/aggregate-1h"),
      now="2026-01-01T00:00:00Z",
  )
  ```

---

## 9. Limitations

1. **Percentile Approximations:** In multi-session aggregation, cross-session percentiles (e.g., latency p50/p95) are calculated using weighted means and maximums across per-session statistics because `ReportV2` stores section summaries rather than raw sample streams.
2. **Single-Session Aggregation:** Phase 12 evaluated a single 1-hour soak session (`soak-1h-20260922`). Multi-session aggregate behavior is validated by unit tests in `tests/test_aggregate.py`.
3. **Duration Scope:** The measured soak duration was 1 hour. Per the non-claims statement, no conclusions regarding 24-hour or multi-day continuous stability are asserted.
